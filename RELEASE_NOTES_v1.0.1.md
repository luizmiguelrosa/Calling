# Calling v1.0.1

First stable milestone of **Calling** — a lightweight internal chat app built to deliver a Slack/Teams-style experience at a fraction of the resource cost, with no embedded Chromium per user.

## Highlights

- **Go backend** — single static binary on [chi](https://github.com/go-chi/chi), with one goroutine per WebSocket connection.
- **Tauri 2 + Angular 22 desktop client** — renders in the OS webview instead of bundling a browser (a few MB vs ~150 MB for Electron), with Tailwind v4 and zard/ui components.
- **JWT authentication** on every route except register and login.
- **Public channels and 1:1 direct messages** over a single real-time WebSocket.
- **PostgreSQL persistence** with type-safe queries generated by [sqlc](https://sqlc.dev/).

## Features

### Authentication

- Register and log in with bcrypt-hashed passwords; roles are `Developer` and `Admin`.
- Login issues an HS256 JWT valid for 1 hour. The signing secret comes from `JWT_SECRET`; a development default is used when it is unset.
- All routes except `POST /users` and `POST /users/login` are protected by JWT middleware.
- The WebSocket handshake accepts the token as `Authorization: Bearer <token>` or, when the upgrade header is present, as a `?token=` query parameter — browsers cannot set headers on a WebSocket handshake.
- The `/chat` endpoint rejects the connection with `401` when the token user no longer exists in the database.

### Chat

- Create and list public channels; DM rooms are excluded from the public list.
- Start a 1:1 DM with `POST /rooms/dm`; the room name is canonicalized as `{smaller_id}-{larger_id}` so a pair can never end up with two rooms.
- Only DM participants may post in a DM room; other users get an error frame.
- Delivery is scoped: public-room messages are broadcast, DM messages go only to the other participant.
- Per-room message history and an online-users list.
- Multiple windows per user are supported — a user stays online until their last connection closes.

### Desktop client

- Login, register, conversation rail, channel view, DM view, and composer.
- Route guards plus an HTTP interceptor that clears the session and returns to login on any `401`.
- The session is persisted, so a restart resumes the signed-in user.
- Server address is resolved once at startup: `CALLING_API_URL` from the process environment (read-only in the app), then the address saved on the **Servidor** page, then the compiled-in default.
- Settings modal with a searchable category tree; **Aparência** holds the dark-mode switch.
- Dark mode follows the OS preference until an explicit choice is made, then persists it.
- Custom title bar with drag region and window controls; auth routes are pinned to 480×720 and the chat maximizes.
- `npm start` runs the UI in a browser for fast iteration, with the window chrome hidden.

## API

| Method | Path | Description | Auth |
|--------|------|-------------|------|
| `POST` | `/users` | Register a user | — |
| `POST` | `/users/login` | Validate credentials, issue a JWT | — |
| `GET` | `/users` | User directory, or one user with `?user_id=` | JWT |
| `GET` | `/history` | Room history with `?room_id=` | JWT |
| `GET` | `/users/online` | Connected user IDs | JWT |
| `POST` | `/rooms` | Create a public channel | JWT |
| `GET` | `/rooms` | List public channels | JWT |
| `POST` | `/rooms/dm` | Create a DM with `receiver_id` | JWT |
| `GET` | `/rooms/dm` | List the current user's DMs | JWT |
| `GET` | `/chat` | WebSocket upgrade | JWT |

WebSocket frames are JSON:

```json
{ "room_id": "<room_id>", "content": "Hello, world!" }
```

## Getting started

**Backend** — Go 1.26+, Docker:

```bash
cd chat-backend
docker compose up -d
go run ./cmd/server     # http://localhost:8080
```

**Desktop client** — Node.js 20+, Rust + [Tauri prerequisites](https://tauri.app/start/prerequisites/):

```bash
cd chat-frontend
npm install
npm run tauri dev
```

Regenerate the database code after editing `db/schema.sql` or `db/queries.sql`:

```bash
cd chat-backend
sqlc generate
```

Full setup notes, request/response examples, and architecture details are in [`README.md`](./README.md).

## Known limitations

This is a POC. Deliberate gaps to be aware of before deploying anywhere real:

- **Permissive CORS and WebSocket origin checks** — every origin is accepted. Fine for local and internal use, not production security.
- **Default JWT secret** — without `JWT_SECRET` the server falls back to `dev-secret-change-me`.
- **Session in `localStorage`** — storage is shared per origin, so a second login in another window replaces the first window's identity.
- **No automated tests** — neither the Go module nor the frontend has a test suite yet.
- **IDs are `time.Now().UnixNano()` strings**, not database-generated UUIDs.
- **Room creation is not transactional** — a room and its participants are written in two steps.

## Updates

### Direct message synchronization
- Incoming DM messages now create the conversation locally immediately, without requiring a re-login. When a user receives a DM from someone they haven't chatted with before, the conversation is automatically added to the sidebar.

### Window size
- Minimum window dimensions set to 800×600 to prevent the chat view from becoming unusable when resized.

### Room list layout
- Room list width reduced from 288px (`w-72`) to 240px (`w-60`) to increase space available for conversation content.
